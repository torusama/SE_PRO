# Findings

- User wants all work scoped below the first Home hero, with the existing hero typography/colors retained. The unwanted outlined house needs removal. The Map and AI home illustrations should resemble the actual function pages rather than generic showcase art.
- Design research supports a clear content flow with focused text/product-preview pairs, using hierarchy through scale, contrast, and spacing rather than excess decoration. Motion will use only opacity and a short vertical translation via an intersection observer, and is disabled for `prefers-reduced-motion`, following web.dev/MDN accessibility guidance.
- The initial web-search parser attempt failed because this connector returns plain text rather than an iterable content array; repeating with the correct result shape returned the design and motion references.
- The unwanted house is the hero SVG's pagoda silhouette at the lower left. It can be removed without touching hero copy, colors, or the rest of the landscape.
- Home currently renders a very large legacy mini-map SVG with a generic four-block grid, while the actual Map page uses a land boundary, access roads, a spiritual park, separated zones A/B/D/E/F/G/H, and grouped family plots in zone C. The Home preview will be replaced visually by a concise code-native schematic with those same landmarks.
- Home's AI preview is a generic scripted chat with circular `AI`/`KH` avatars, unlike the live Agent's bot header, helper copy, prompt cards, and composer. The replacement will mirror those stable live UI elements without pretending to be a real conversation.
- The current section spacing is dominated by 100px default padding, a 160px decorative divider, and 64–80px grid gaps. Lower sections need a tighter 72–88px rhythm and calmer card treatment.
- Follow-up review: the current Home Agent preview is a static product card and its wrapper navigates directly to the AI route. The requested behaviour is a lively, staged conversation preview with no navigation on the illustration itself and one explicit button to open AI. Home currently has only a service feature card, so a concise service introduction needs to be restored as its own readable block.
- The Home Service page categorises its actual offerings as an táng, chăm sóc & vệ sinh, and tưởng niệm & lễ nghi. The restored Home introduction uses those real groups rather than invented offerings.
- Direct Chromium capture confirmed the dev server responds, but anchor capture cannot inspect lower sections because the browser resolves the fragment before React renders the target; an oversized viewport is also unsuitable because the intentional `100vh` hero expands with it. Source review, lint, and the production build are the verification for the lower sections.
- The user's screenshot exposes a real global CSS collision: `TransferPage.css` declares an unscoped `.section-title { display:flex; justify-content:space-between; }`, while Home reused the same generic class. Because page CSS is bundled globally, Home's white and teal heading fragments are being pushed to opposite edges. Home typography must use Home-specific class names and scoped selectors.
